Changes
Making changes and adding them to the main branch may seem intimidating,
so to help we've created this handy checklist that outlines all the steps for success!
Adding changes to your branch
This stages all changes. You can swap out "." with a file name if you want more control over which files you stage
This makes a commit with all the files you staged. The message should be short and describe the changes you've made.
Commit often so if you need to do a roll-back, you don't lose a lot of good code unrelated to the problem
Pushes the changes to the remote repository so others can access it too
Keep main branch up to date
Change to the main branch
Get changes that have been made to the main branch since the last time you pulled. You should do this often to avoid large amounts of merge conflicts when you push your changes to the main branch later on
Merge main into branch and resolve conflicts
Change back to your branch
Adds the changes that have been made to main since last time
In case there are any conflicts between the newest version of main and the code on your branch, solve these before continuing
Pushes the changes to the remote repository so others can access it too
Add your changes to the main branch
This allows collaborators to review your changes before they get added to the main branch. Never add unnaproved code to the main branch
Change to the main branch
Merge the changes from your branch into the main branch. Only do this to code that has been reviewed and approved
Pushes the changes to the main branch in the remote repository so others can access it too
